# Authoring and evidence contract

Use `grade-10/batches/g10-ch2-ex2-1.json` as the real exercise example. Each batch has `schemaVersion: 1`, a stable `batchId`, numeric `grade`, existing numeric string `chapter`, a site-relative `module` path, `sources`, `inventory`, `records`, `mapping`, `verification.script`, and `tamilStatus` (`pending` or `source-verified`).

Each source records `id`, `grade`, `language`, `title`, actual `edition`, canonical `url`, PDF `sha256`, `verification: "verified"`, `imprintPdfPage` and `imprintVisualChecked: true`. Page-image checks are editorial evidence, not an assertion inferred by the tool. Source files remain outside the repository.

The inventory has an explicit `completeChapter` boolean and `exercises`. Each exercise has `id`, `complete`, and sequential `questions`; `complete` means its source inventory is exhaustive. Each question has string `number`, `parts` (`["whole"]` for one unlabelled task, otherwise exact labels), `sourceId`, positive integer `printedPages` and `pdfPages`, `visualChecked`, `requiredFigures`, `tables`, `graphs`, `mcq`, and `answerKey` (null when absent). A blocked question has `status: "blocked"` and `blockedReason`; it cannot be registered as solved. Keep source gaps visible.

`records` use the existing runtime schema: stable globally unique `id`, `classNum`, `chapter`, `exercise`, language keyed `topic`, `label`, `title` and `q`, ordered `steps` with explanations and optional string `eq`, STRING `answer`, `kind: "textbook"`, canonical `source`, `reference`, and optional `figureSrc`. An English-only record leaves `q.ta` absent and uses an explicit English-only/Tamil-pending notice in its Tamil UI label. Its English fallback is never counted as verified Tamil. The final answer remains the existing end step in How It Works.

Each mapping has `recordId`, `exercise`, `question`, exact covered `parts`, `sourceId`, checked `sourceText.en`, `visualChecked.en`, `printedPages` and `pdfPages`. A sourced Tamil question also requires `tamilSourceId`, `sourceText.ta`, `visualChecked.ta`, matching Tamil printed/PDF page locators and complete Tamil steps. Every source task is mapped once. A split question must retain the original stem needed to understand its subpart.

The CommonJS verifier exports a synchronous function taking `{records, mapping, inventory}` and `{hashRecord}`. It independently checks actual mathematics and returns `{checks: [{recordId, parts, passed, method, recordSha256}]}`. `recordSha256` must be `hashRecord` of the current complete record. Hashes invalidate stale evidence; they do not prove mathematics. The pilot combines reviewed solution hashes with polynomial identities, exhaustive parity arguments, independent divisor calculation, every rendered Euclidean equality, remainder bounds and substitution. Proof review is required in addition to any finite numerical checks.

For a chapter produced through several exercise batches, place its separate authoritative source inventory in `grade-N/chapters/*.json`: `{schemaVersion:1, grade, chapter, sources, inventory:{completeChapter:true, headingScanVerified:true, chapterExerciseIds:[...], exercises:[...]}}`. It owns no duplicate records. Reconciliation compares the union of passing batch mappings with that full source inventory. A chapter is complete only when every expected task is verified and integrated. Missing or unverified chapter inventories keep denominators and percentages null.

`validate-all` checks the collection, including duplicate batch/module ownership, source-task overlap, folder ownership, integrated records and authoritative chapter inventories. Save per-batch JSON reports under the grade's `reports/`. A failed report is never counted as verified progress. `checkpoint --grade N` atomically refreshes only that grade's inventory and preserves operator, test and release facts.

`register` refuses a different existing module. To correct an already registered batch, edit its single authoring manifest, renew source and mathematical evidence, compute the current module SHA-256 and use `correct BATCH --expected-module-sha HEX`. This explicitly checks the previous module, preserves stable IDs and unrelated records, and regenerates deterministically. It never authorizes replacing Grade 10 Chapter 1. Rerun the affected batch gates and full release checks after corrections.
